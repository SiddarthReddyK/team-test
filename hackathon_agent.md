# HACKATHON RULES

We are a team participating in an 8-hour virtual hackathon (9 AM–5 PM).

The problem statement will be revealed at 9 AM.
AI-generated code is allowed.

## OUR GOAL

Build a working, polished and demonstrable solution within 8 hours.

Priority:

1. Core requirements
2. Working MVP
3. Testing and stability
4. UI/UX
5. Extra features

Do not over-engineer.

## WHEN THE PROBLEM IS GIVEN

First understand it and identify:

- What problem are we solving?
- Who are the users?
- What are the MUST-HAVE features?
- What are the NICE-TO-HAVE features?
- What data/APIs are required?
- What is the simplest suitable tech stack?
- How should the application be structured?

Create a short implementation plan before coding.

## DEVELOPMENT RULES

- Check the existing repository before changing anything.
- Keep the tech stack simple.
- Prefer real-time/dynamic data when required.
- Static JSON is only for prototyping/mock data.
- Validate user input properly.
- Do not blindly copy AI-generated code; understand and adapt it.
- Test code after implementing major features.
- Do not expose API keys or secrets.
- Prefer local/offline fallbacks when practical.
- Use Git properly.

## TEAM WORK

We work as collaborators through GitHub.

Before working:

- Check TEAM.md.
- Work only on your assigned task.
- Avoid modifying another member's files.
- Pull the latest changes.

When generating code:

- Always give the exact file path.
- Prefer the complete file when practical.
- Clearly say whether the file is NEW or UPDATED.
- Do not change unrelated files.

After finishing:

- Test your work.
- Tell us which files changed.
- Give a suggested Git commit message.
- Mention anything another teammate needs to know.

## UI

Create a clean, responsive and consistent UI with:

- Good spacing
- Clear navigation
- Proper validation
- Loading/error/empty states

Avoid unnecessary animations, clutter and excessive styling.

## FINAL CHECK

Before submission:

- All MUST-HAVE features work
- Main user flow works
- No major errors
- UI is responsive
- Dynamic data works where required
- No exposed secrets
- Build works
- Git repository is organized
- Demo works
